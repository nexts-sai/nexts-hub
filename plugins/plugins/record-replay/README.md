# Record & Replay

Nexts plugin backed by [OpenAdapt Flow](https://github.com/OpenAdaptAI/openadapt-flow). Includes one Skill, a local stdio MCP adapter, and upstream Skill/MCP export. Version 0.1.0 supports browser recordings and rehearsal replay through chat tools; it has no separate visual editor or native desktop backend.

## Setup

Requires Node.js 18+ and Python 3.10–3.12. Install Flow into a dedicated environment outside the plugin folder (example from a user-owned tools directory):

```powershell
uv venv --python 3.12 record-replay-env
uv pip install --python record-replay-env/Scripts/python.exe "openadapt-flow[browser]==2.0.0"
record-replay-env/Scripts/python.exe -m playwright install chromium
```

Set `NEXTS_RECORD_REPLAY_PYTHON` to the **absolute Python executable path** in that environment, in the contributed MCP server environment or before starting Nexts. On macOS/Linux use `record-replay-env/bin/python`. Default is `python` on PATH. The adapter disables Flow's automatic browser download; provision Chromium explicitly above. `PLAYWRIGHT_BROWSERS_PATH` can point to a separate browser storage directory (use the same value for installation and the MCP process).

Install/enable this plugin in Nexts. It needs a host supporting `${NEXTS_PLUGIN_ROOT}` in contributed MCP command, arguments and environment values. The manifest uses Nexts `contributes.mcpServers`; `.mcp.json` is also provided for compatible clients. For other MCP clients replace `${NEXTS_PLUGIN_ROOT}` with the absolute installed package path.

Artifacts default to `%LOCALAPPDATA%/Nexts/record-replay` on Windows, or `~/.local/share/Nexts/record-replay` elsewhere. Override with an absolute `NEXTS_RECORD_REPLAY_DATA`. Use a private directory, not a shared folder. Do not run two MCP instances against the same root concurrently.

## Use

Ask “帮我录制一个浏览器操作”. The assistant checks dependencies, opens the recorder and waits while **you** demonstrate. Tell it to finish; it saves and compiles the recording. Supply fields as parameters at recording time to change their values on replay. Ask to replay a workflow with your desired URL and parameters, then inspect the result.

Tools: `flow_status`, `flow_list`, `flow_record`, `flow_stop_recording`, `flow_compile`, `flow_replay`, `flow_job`, `flow_cancel`, `flow_export`.

The MCP adapter launches actual Flow operations, not simulated workflows. Each long operation returns a job ID immediately. Poll it. Operations are serialized. Existing IDs cannot be overwritten. Replay request IDs are persisted before launch and cannot be reused with different inputs. After an uncertain response, use the same ID to inspect the existing run, never create another operation automatically. Interrupted runs require reconciliation. Jobs stop after 30 minutes; recordings should be finished before that limit.

Flow's ordinary `replay` is a rehearsal, and exit 0 can mean `COMPLETED_UNVERIFIED`. This plugin does not build production certification/effect-verifier contracts. It reports verified success only from an explicitly verified report. A cancelled run may already have written data. Logs, screenshots, parameters and reports are private local artifacts; cancelling/uninstalling does not delete them.

`flow_export` invokes the official `emit-skill` or `emit-mcp` exporter. Generated MCP servers require `mcp` installed in the same Python environment and replay without an independent record check. Exports are not automatically installed, registered or uploaded.
